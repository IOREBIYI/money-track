MoneyTrack

A simple, private personal finance tracker for Android. Record income and expenses, set monthly budgets, see where your money goes. Your transactions never leave your phone.

Android 8.0+ Kotlin + Jetpack Compose Room (on-device) Firebase Auth No ads, no analytics
Features Privacy Architecture Flows Data model Quality & release

What it does

Transactions

Add, edit and delete income and expenses with category, date and note. Browse by month.

Budgets

Set a monthly limit per category and watch the progress bar fill.

Reports

Spending by category, plus a six-month income vs. expenses chart.

Backup

Export to CSV and restore from CSV. Handy for moving to a new phone.

Accounts

Sign up, sign in and password reset by email. In-app account deletion.

Currencies & theme

39 display currencies (no conversion). Ledger-style design with a matching dark mode.

Private by design

Transactions and budgets are stored only in the on-device database and are never uploaded. Only your email and user ID are held by Firebase Authentication so you can sign in.

No ads, no analytics, no trackers. See PRIVACY.md and ACCOUNT_DELETION.md.

Architecture

MoneyTrack uses MVVM: Compose screens observe StateFlows from ViewModels, which read and write a Room database. Firebase Auth is the only external service.

LayerWhereRole
UIui/Compose screens, four tabs, add/edit dialog, theme
StateMoneyViewModel, AuthViewModelExpose flows, launch writes
Datadata/Room DAO and entities, CSV, currencies
Authauth/AuthRepository with Firebase and "unconfigured" implementations, validation, error mapping

Key flows

  1. Firebase configured?No → "Accounts aren't set up" message.
  2. Already signed in?Yes → straight to the main app.
  3. Sign in screen: sign in, create account, or forgot password.
  4. Validate input locallyEmail format; password 8+ characters with a letter and a digit (sign up).
  5. Call Firebase Auth.
  6. Success?Errors are mapped to friendly messages (wrong credentials, email in use, network, too many attempts).
  7. Main app opens with four tabs.
  1. On the Transactions tab, tap + (or a row to edit).
  2. Enter type, amount, category, date and note.
  3. Amount valid and above zero?The save button stays disabled until it is.
  4. ViewModel saves to Room.
  5. Room emits a new list; transactions, budgets and reports update automatically.
  1. Settings tab → Export: choose a location, all transactions are written as CSV.
  2. Settings tab → Restore: choose a CSV file.
  3. File valid?Checks header, each row, amount and date. On failure nothing changes and the reason is shown.
  4. On success all current transactions are replaced and a "Restored N transactions" message appears.
  1. Settings tab → Delete account and enter your password.
  2. Firebase re-authenticates you, then deletes the account.
  3. Success?No → error shown and the account is kept.
  4. Back to the sign in screen.

Quality and release

  • Instrumented tests: Room DAO and sign-in flows against the local Firebase Auth emulator.
  • CI on every pull request: unit tests, lint, debug build, emulator tests. No release secrets in CI.
